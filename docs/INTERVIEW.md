## 1. 项目陈述模板

### 1.1 一分钟版本

> 这个项目做的是数字和小写字母验证码识别。输入是一张 60×160 的灰度图，输出是验证码字符串。它没有先切割单个字符，而是采用 CRNN：CNN 提取局部视觉特征，把特征图沿宽度方向转成序列，两层双向 LSTM 建模字符之间的上下文，最后用 CTC 解决图像序列与字符标签之间的对齐问题。模型有 41 个时间步、37 个输出类别，其中 36 个是字符，1 个是 CTC blank；推理时使用贪心解码。原 Notebook 记录的整串完全匹配准确率最高为 99.00%，最后一次为 98.67%。这个结果基于合成验证码，不能代表真实网站验证码的泛化能力。整理项目时，我把 Notebook 拆成了数据生成、训练、评估和预测入口，保留旧权重兼容性，并补充了跨训练/测试集标签去重和 CER 指标。

### 1.2 三分钟版本

> **问题**：普通图像分类只输出一个类别，而验证码要输出一个字符串。直接切字符又会受到粘连、旋转和位置变化影响，所以我使用端到端的 CRNN，让模型从整张图直接预测序列。
>
> **模型**：输入先归一化到 [-1, 1]。CNN 有 4 层卷积和 3 次池化，前两次池化同时压缩高和宽，最后一次池化高度步长为 2、宽度步长为 1，避免时间维被过度压缩。最终特征图是 256×7×41，把每个宽度位置上的通道和高度展开成 1792 维，就得到长度 41 的序列。两层双向 LSTM 每个方向 256 个隐藏单元，输出拼接为 512 维，再映射到 37 类。
>
> **训练与对齐**：标签只有字符串，没有每个字符的坐标。CTC 会枚举思想上的所有合法对齐路径，但用动态规划高效求和，因此不需要人工标注字符位置。blank 既表示没有字符，也用来分开连续重复字符。例如 `aa` 需要类似 `a-blank-a` 的路径，直接合并相邻重复项会得到一个 `a`。
>
> **实验**：原 Notebook 第 45 轮记录 99.00% 的整串准确率，第 50 轮和最终结果为 98.67%。这些数字只说明模型在同一类合成数据分布上有效，原仓库没有完整保留数据规模和划分，所以我不会把它包装成真实场景 99% 准确率。
>
> **整理与改进**：我将重复的 Notebook 代码模块化，修正了旧注释中的尺寸，提供可复现的数据生成、训练、断点续训、评估和单图预测命令；旧的最佳权重可以严格加载。工程上增加了训练/测试标签去重、空数据与非法标签检查、CPU/CUDA 兼容和字符错误率。下一步重点是使用独立真实测试集评估泛化，再考虑 prefix beam search、错误样本分析和模型轻量化。

## 2. 任务为什么适合 CRNN

验证码识别是一个**输入为图像、输出为字符序列**的问题，难点有三个：

1. 字符数量属于序列输出，不是单标签分类。
2. 字符位置、间距和形变不固定，逐字符分割容易失败。
3. 训练标签通常只有完整字符串，没有逐字符边界。

CRNN 的三个部分正好分别处理这些问题：

- **CNN**：提取笔画、边缘和局部形状等视觉特征。
- **RNN**：沿水平方向建模上下文，例如左侧形状和右侧形状是否共同支持某个字符判断。
- **CTC**：在没有字符位置标注的情况下学习图像到字符串的对齐。

这里的“序列”不是把原图随意拉平，而是把 CNN 特征图的每个水平位置看成一个时间步。

## 3. 逐层原理与张量尺寸

### 3.1 预处理

原图读取为灰度图并缩放到宽 160、高 60：

```text
img_norm = (img / 255 - 0.5) / 0.5
```

像素由 `[0, 255]` 映射到 `[-1, 1]`，输入张量为 `[B, 1, 60, 160]`。训练和预测必须调用同一套预处理，否则权重对应的输入分布会改变。

### 3.2 CNN 特征提取

| 阶段 | 输出尺寸 `[B, C, H, W]` | 作用 |
|---|---:|---|
| 输入 | `[B, 1, 60, 160]` | 单通道灰度图 |
| Conv 64 + 第一次 2×2 池化 | `[B, 64, 30, 80]` | 提取低层特征，降低分辨率 |
| Conv 128 + 第二次 2×2 池化 | `[B, 128, 15, 40]` | 提取更抽象的形状特征 |
| Conv 256 + Conv 256 | `[B, 256, 15, 40]` | 增加表达能力，尺寸不变 |
| 最后一次非对称池化 | `[B, 256, 7, 41]` | 高度继续压缩，宽度基本保留 |

最后一层池化参数是：

```python
nn.MaxPool2d(kernel_size=(2, 2), stride=(2, 1), padding=(0, 1))
```

宽度计算为：

```text
W_out = floor((40 + 2×1 - 2) / 1 + 1) = 41
```

所以时间步是 **41**，不是旧 Notebook 注释中的 40。高度计算为：

```text
H_out = floor((15 - 2) / 2 + 1) = 7
```

为什么最后一次不继续把宽度减半？因为宽度对应序列长度。如果宽度太小，每个字符可分到的对齐位置太少，CTC 学习会更困难；保留 41 个位置能让 5 个字符有较充足的对齐空间。

### 3.3 从特征图变成序列

CNN 输出为 `[B, 256, 7, 41]`，代码执行：

```python
x = x.view(B, C * H, W).permute(2, 0, 1)
```

得到 `[41, B, 1792]`，其中 `1792 = 256×7`。可以理解为：对 41 个水平位置，每个位置都保留整个垂直方向上的视觉证据。

这里采用 `[T, B, C]` 是因为 PyTorch LSTM 默认 `batch_first=False`。CTC loss 在当前实现中也接收同样的时间优先布局。

### 3.4 双向 LSTM

```python
nn.LSTM(
    input_size=1792,
    hidden_size=256,
    num_layers=2,
    bidirectional=True,
    dropout=0.4,
)
```

- 前向 LSTM 利用左侧上下文。
- 后向 LSTM 利用右侧上下文。
- 每个时间步把两个方向的 256 维输出拼成 512 维。
- 两层堆叠提升序列建模能力。
- `dropout=0.4` 作用于 PyTorch 多层 LSTM 的层间输出，不是简单地对所有输入和最终输出都做 dropout。

随后全连接层把 512 维映射为 37 维，输出 `[41, B, 37]`。网络本身返回 logits，训练时才计算 `log_softmax`，预测时直接对 logits 做 `argmax` 即可。

模型约有 **676 万个参数**，主要参数集中在 LSTM，而不是 CNN。

## 4. CTC 的核心原理

### 4.1 为什么需要 CTC

网络给 41 个时间步都输出一个类别，但标签只有 5 个字符。我们不知道哪个时间步对应哪个字符，也无法直接把 41 个输出和 5 个标签做普通交叉熵。

CTC 的做法是允许多个时间步对应同一个字符，并加入一个额外的 blank 类。它对所有能折叠成目标字符串的路径求概率和，因此训练不需要字符级位置标注。

### 4.2 路径、折叠与概率

设网络在时刻 `t` 的输出为 `y_t`，一条对齐路径为 `π`。在条件独立假设下：

```text
p(π | x) = ∏_t p(π_t | x)
```

定义折叠操作 `B`：先合并相邻重复类别，再删除 blank。例如：

```text
B(a, a, -, b, b) = ab
B(a, -, a, -, b) = aab
```

目标标签 `l` 的概率是所有合法路径概率之和：

```text
p(l | x) = Σ_{π: B(π)=l} p(π | x)
L_CTC = -log p(l | x)
```

合法路径数量可能非常多，但实际计算使用类似 HMM 前向算法的动态规划，而不是暴力枚举。

### 4.3 blank 的两个作用

1. 表示当前时间步不输出字符，允许多余时间步存在。
2. 分隔两个相同字符，使模型能够表达 `aa`、`00` 等连续重复标签。

因此，“去重复、去 blank”的顺序和 blank 的语义都非常重要。

### 4.4 当前贪心解码

当前实现逐时间步取最大类别，然后合并相邻重复类别并删除 blank：

```text
logits -> argmax -> merge repeats -> remove blanks -> string
```

优点是简单、快、无需额外参数。缺点是逐时刻最优不等于整串最优，也没有使用验证码长度或语言先验。

Prefix beam search 会保留多个候选前缀，通常能得到更好的整串概率，但计算更复杂。如果业务规定验证码固定为 5 位，还可以在解码时加入长度约束，但必须同时报告这种先验带来的收益。

## 5. 数据、训练与评估

### 5.1 数据标签

图片文件名就是标签，例如 `gig4i.png` 对应 `gig4i`。字符表为：

```text
0123456789abcdefghijklmnopqrstuvwxyz
```

索引 0～35 对应字符，索引 36 是 blank。一个 batch 中，标签拼接成一维 `targets`，另用 `target_lengths` 记录每张图片的标签长度；`input_lengths` 则记录每个样本的有效时间步数，当前固定为 41。

整理后的生成器会让训练集和测试集的标签互斥，避免同一个字符串同时出现在两边造成数据泄漏。原 Notebook 的简单随机生成没有显式处理这一点。

### 5.2 原训练设置

最佳权重对应的 Notebook 训练代码使用：

- AdamW，学习率 `1e-4`。
- `ReduceLROnPlateau`，根据训练 loss 降低学习率。
- CUDA 下自动混合精度与 `GradScaler`。
- 每 5 轮评估一次。
- 保存最佳模型和包含优化器、调度器状态的 checkpoint。

混合精度主要用 FP16 降低显存占用并加速兼容 GPU 上的运算，`GradScaler` 通过放大 loss 降低 FP16 梯度下溢风险。CTC 的对齐计算和 `log_softmax` 仍需关注数值稳定性。

### 5.3 为什么不能只看 loss

CTC loss 是负对数似然，不直接等于识别错误率。loss 下降通常意味着目标序列概率提高，但最终还要观察解码结果。

本项目至少看两个指标：

- **整串完全匹配准确率**：只有预测字符串和真实字符串完全一致才算正确。这是原 Notebook 的 accuracy。
- **字符错误率 CER**：预测与标签之间的最小编辑距离总和，除以真实字符总数。

```text
CER = (替换数 + 删除数 + 插入数) / 真实字符数
```

例如 100 个样本各 5 个字符，若只有 2 个样本各错 1 个字符，则整串准确率为 98%，CER 为 `2/500=0.4%`。整串指标更严格，CER 更能反映错误严重程度。

## 7. 高频面试问题与参考回答

### Q1：为什么不用普通 CNN 分类？

普通 CNN 分类通常输出固定一个类别。验证码需要输出字符串，若直接做 5 个分类头，会强依赖固定字符数和位置划分；若先切字符，又容易被粘连和形变影响。CRNN 保留序列结构，并用 CTC 免除字符级位置标注，更适合这个任务。

### Q2：为什么不用 36 类，而是 37 类？

36 类是数字和小写字母，额外的第 37 类是 CTC blank。blank 用来吸收多余时间步，并分隔连续重复字符，索引为 36。

### Q3：CTC 最大的价值是什么？

它解决输出序列和标签序列长度不同、对齐未知的问题。训练只需要完整字符串，不需要每个字符的 bounding box 或起止位置。

### Q4：CTC 是不是完全不需要对齐？

不是。它是不依赖人工对齐标注，但内部仍然对可能的对齐路径建模并求和。说“完全不需要对齐”不准确。

### Q5：为什么 `aa` 不能由连续两个时间步的 `a` 表示？

因为 CTC 折叠会先合并相邻重复项，`aa` 会被折成一个 `a`。通常需要 `a-blank-a` 这样的路径才能保留两个 `a`。

### Q6：CTC 有什么假设或局限？

常见形式假设各时间步在给定输入特征后的输出条件独立，整串概率由对齐路径连乘得到。它本身不像自回归模型那样显式建模输出字符之间的条件依赖。贪心解码还会进一步放弃全局候选搜索。

### Q7：为什么网络输出 41 个时间步？

输入宽 160，前两次池化后变成 40；最后一次池化宽方向 kernel=2、stride=1、padding=1，所以得到 `40+2-2+1=41`。CTC 的 `input_lengths` 应从实际输出读取，而不是硬编码为 40。

### Q8：为什么采用非对称池化？

高度方向需要把垂直视觉信息逐步压缩并聚合，宽度方向则承担序列时间维。如果宽度也持续减半，序列会过短，字符定位和 CTC 对齐空间都会变差。

### Q9：为什么使用双向 LSTM？有什么代价？

验证码图片在推理前已经完整可见，因此可以同时利用左右上下文，通常比单向 LSTM 更有利于字符判别。代价是计算和参数增加，而且必须等完整序列到齐，不适合严格流式识别。

### Q10：LSTM 参数量为什么比 CNN 还大？

LSTM 第一层输入维度为 1792，每个方向有 4 个门，权重矩阵同时作用于输入和隐藏状态，并且双向各有一套参数。第一层双向 LSTM 约有 420 万参数，是整个模型最大的部分。

### Q11：为什么用 BatchNorm？

卷积后的 BatchNorm 能稳定中间特征分布，使训练更容易。评估时必须调用 `model.eval()`，否则会继续使用 batch 统计量，结果可能不稳定。

### Q12：为什么用 AdamW，而不是 SGD？

AdamW 为不同参数维护自适应学习率，通常在小项目上更容易较快收敛；解耦权重衰减也便于正则化。它不是必然优于 SGD，最终仍取决于数据、超参数和验证结果。

### Q13：Adam 和 AdamW 的区别是什么？

经典 Adam 常把 L2 正则项混入梯度后再做自适应缩放；AdamW 把权重衰减从梯度更新中解耦。两者在使用 L2 时并不等价。

### Q14：混合精度为什么需要 GradScaler？

FP16 的表示范围较小，小梯度可能下溢为 0。先缩放 loss，反向传播后梯度也被放大；优化器更新前再恢复尺度，从而降低下溢风险。

### Q15：为什么保存两个权重文件？

`crnn_best_model.pth` 只保存模型参数，用于部署预测；`crnn_checkpoint.pth` 还保存 epoch、优化器、调度器和整理后新增的 scaler 状态，用于断点续训。只加载模型参数并不等于完整恢复训练状态。

### Q16：整串准确率和字符准确率哪个更重要？

业务上通常更关心整串准确率，因为错一个字符整个验证码就失败。但字符级指标或 CER 能帮助判断模型是偶尔错一个字符，还是大量输出完全错误，所以两者应结合。

### Q17：为什么训练/测试标签重复会泄漏？

如果相同字符串甚至相同图片同时出现在训练集和测试集，模型可能记住样本，测试准确率会偏乐观。更严格的做法除了标签互斥，还应使用不同随机种子、不同生成参数甚至不同生成器做独立测试。

### Q18：99% 是否说明项目已经能识别真实验证码？

不能。它只说明原模型在原合成分布上表现好。真实验证码可能有不同字体、颜色、噪声、遮挡、粘连和字符集，需要独立外部测试才能判断泛化。

### Q19：如果测试集准确率很高但真实效果差，你怎么排查？

先确认预处理一致，再比较训练与真实数据的字体、尺寸、背景、字符集和噪声分布；检查是否存在测试泄漏；抽样分析错误类型；最后用跨生成器或真实数据做验证，而不是继续只看原测试集。

### Q20：训练 loss 长期不动，你会如何排查？

先检查标签映射、blank 索引、输入/目标长度和解码是否正确，再检查梯度是否为零、NaN 或异常大，学习率是否合适，以及数据是否过于困难。CTC 在训练初期输出分布接近均匀，可能经历较长的对齐学习阶段；不能仅凭“loss 不降”就断定是局部最小值。

### Q21：如何支持可变长度验证码？

数据集、标签拼接和 CTC 本身支持变长标签。只要字符仍在字符表内，并且有效时间步足以对齐目标即可。对于含相邻重复字符的标签，所需最短对齐长度还包含额外 blank。当前图像宽度固定，因此输入时间步固定为 41。

### Q22：能否把图片改成其他尺寸？

预处理可以把图片缩放到其他尺寸，但当前 LSTM 的 `input_size=1792` 要求 CNN 输出高度为 7。改变输入高度可能破坏该维度，旧权重也不能直接兼容；需要重新设计自适应池化或重新训练。

### Q23：贪心解码有什么问题？如何改进？

它逐时刻取最大概率类别，可能错过整串概率更高的组合。可以用 prefix beam search 保留多个前缀，并结合固定长度先验；但要权衡延迟和复杂度，也不能用语言模型把不符合真实分布的字符串“纠正”成看似合理的结果。

### Q24：如果过拟合，你会怎么处理？

先通过训练/验证曲线和错误样本确认，而不是仅凭某一个指标。可以增加生成数据和字体、噪声、旋转等增广，调整权重衰减或 dropout，使用独立验证集早停。不要根据测试集反复调参，否则测试集也参与了模型选择。

### Q25：为什么最终结果比最好结果低一点？

第 45 轮是 99.00%，第 50 轮是 98.67%，说明最后几轮在测试集上有轻微波动，不能据此证明严重过拟合。保存最佳权重就是为了避免只使用最后一轮。差异对应的样本数和统计波动也应纳入判断。

### Q26：如何进一步压缩或加速模型？

可以先统计各阶段延迟，再减少 LSTM 隐藏单元、层数或输入特征维度，尝试 GRU、深度可分离卷积、量化或 ONNX/TensorRT 部署。任何改动都要重新验证准确率，旧权重不能直接加载到形状不同的新模型。

### Q27：这个项目中最重要的工程细节是什么？

我认为是训练、评估和预测共享完全一致的字符表、预处理、blank 索引和模型形状；其次是正确保存 `input_lengths` 与 `target_lengths`。很多“网络没问题但结果异常”的情况，实际来自这些接口约定不一致。

### Q28：如果重新做一次，你优先改什么？

优先把数据实验做严谨：固定并记录数据规模、随机种子和划分，增加独立验证集与跨生成器测试集，保存错误样本和配置。之后再比较贪心与 beam search、LSTM 容量和增广策略。先建立可信评估，再追求更复杂模型。

## 8. 面试时的简洁收尾

> 这个项目虽然网络不大，但覆盖了序列图像识别的完整链路：视觉特征、序列建模、弱监督对齐、解码和序列级评估。我最大的收获不是堆出了一个 CNN+LSTM，而是理解了各阶段张量约定和 CTC 对齐假设，也知道合成数据上的高准确率与真实泛化之间还有明显距离。
